# Original Windows optical beam region (native x86)

**Ground truth:** the user's authentic extracted CrazyMachines.exe, SHA-256 `51f9beecd9842c67834da9c4fc73be7a1452c9e8149d059729b130a2b9d601e6`.

The native method at `0x409650–0x40985B` is called inside the original solar/optical path at `0x44FD6E`, `0x44FDC6`, and `0x44FEC3`. The complete instruction chain and three immutable constants were checked against the owner's PE32 using the new read-only SHA-gated auditor. Nothing proprietary is included in the Git repository.

The method projects the original source and target into XY, subtracts them, calculates squared distance, rejects values outside the beam object's squared bounds `+0x34` and `+0x38`, and compares `acos(dot(normalizedForward, normalizedDelta))` to the native `+0x40` angular cutoff. Its resulting signal is the clamped product `(1-(angle*beam[+0x44])^2) * (1-(distanceSquared-beam[+0x34])*beam[+0x3C])`. The output direction is the normalized XY delta.

**Important corrected discovery:** original x87 condition-code branches accept **equal** lower and upper squared-distance limits and **equal** angular limit. The native tests are `test ah,0x05; jp` at `0x4096DE` and `test ah,0x41; jne` at `0x4096F5` and `0x409786`. A prior local interpretation treated these as strict comparisons; the Swift port tests the inclusive case.

`CMOriginalWindowsBeamRegion` implements the recovered scalar/geometry formula. `CMOriginalWindowsOpticalSample` combines it with real measured UCM sightline occlusion and the separately recovered solar-signal attenuation. **No solar current, GOAL or fictional light ray is generated by simple proximity or line of sight.** Real beam parameter values `+0x34..+0x44`, per-emitter orientation, mirror/reflection paths and the remaining native update callbacks must still be reconstructed and connected to production runtime. Experimental geometry and scalar unit tests do not prove the original game is playable or that all 102 Windows puzzles can be solved on iOS.

Private reproduction: `python3 tools/audit_windows_beam_exe.py /private/path/CrazyMachines.exe`.

## Original Win32 pocketlamp switch and source-state evidence

At 0x434A9A, the owner's original x86 game selects the literal `tmo_light_pocketlamp` (exact string VA 0x4EA470). A click checks the element +0xEC against zero, writes exact 1.0 at 0x434ACA if zero or exact 0.0 at 0x434AD9 otherwise. The resulting +0xEC is separately compared to the internal +0xF0 scalar at 0x434AE6..0x434AFF before dispatcher 0x44B460 is called at 0x434B12. The original solar-ray collector at 0x44FE53..0x44FE66 also requires pocketlamp +0xEC to be nonzero before it samples the real beam at 0x44FEC3.

The iOS gameplay session now preserves these exact active/inactive values by original object ID, and the 3D player lets the user toggle them by tapping the authentic pocketlamp UCM body/glass when simulation is running. Its existing original `light_pocketlamp_glow.tga` billboard is switched with the source state. This does not fabricate a GOAL just because the player taps the lamp: mapping original +0xF0 physics state to SceneKit, source/receiver orientation and actual photon interception are still needed. On pause, no state toggles; on reset, each source returns inactive. Portable and iOS CI checks exercise the behavior.
