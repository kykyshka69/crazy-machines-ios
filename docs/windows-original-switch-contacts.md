# Original Windows tmo_power_switch contact gate — verified x86 (2026-11-22)

Based on the user-owned original `CrazyMachines.exe`, SHA-256 `51f9beecd9842c67834da9c4fc73be7a1452c9e8149d059729b130a2b9d601e6`. `tools/audit_windows_switch_contacts.py` checks **23 instruction sites**, floats `1.0` and `−1.0`, and `tmo_power_switch` selector in the original PE32. No game executable/source bytes are committed.

At `0x44C98B–0x44CA2B`, after propagation has reached the **real** switch device, the original calls `0x41F7C0` and `0x41F4D0` to obtain two internal physics components. It reads the first scalar at **`+0xEC`** and the other at **`+0xC8`**; the `fucompp` equality branches compare both with the *same sign* of ±1. **If the selected component is exactly +1 and the mate is not +1, it writes ZERO to electrical `+0x40`. If the selected component is exactly −1 and the mate is not −1, it also writes ZERO.** Matched pairs `(1,1)` and `(-1,-1)` preserve incoming electricity. Any *finite* selected component other than ±1 does not take a zero-write branch. Unknown/nonfinite evidence fails closed on iOS, instead of inferring contact.

`ios/CMOriginalWindowsSwitchContactGate.swift` implements this verified exact-state check. `CMOriginalPowerCircuit.experimentalNetworkSignals(switchContactsByDeviceID:)` lets a physically observed pair of authentic switch component states override the earlier experimental `closedSwitchIDs` toggle; when contact mismatch is observed, the switch itself is not credited as powered. Existing user-tapped prototype switches are intentionally retained only as fallback **when actual contact component states are unavailable**.
